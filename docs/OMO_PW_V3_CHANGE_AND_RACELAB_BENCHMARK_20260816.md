# OMO-PW V3 変更点とRaceLabベンチマーク

更新日: 2026-08-16 JST

## この文書の目的

この文書は実装指示書ではなく、YujiがV3の範囲を判断するための材料である。

1. V2で現在できていること。
2. V2からV3で変更すること。
3. RaceLabから合法的に取り込める機能思想・運用・課金導線。
4. OMORAYが真似るべきでないこと。

他社のコード、画像、文章、商標、画面デザインはコピーしない。一般的な機能思想、ワークフロー、情報設計、価格導線をOMORAY独自の実装へ変換する。

## V2の現状

### すでにローカル・決定論で動いている部分

| 領域 | V2の現状 | 評価 |
|---|---|---|
| iRacing取得 | Windows Bridgeがshared memoryを直接読む | V3でも維持 |
| セッション状態 | Practice/Qualify/Race、搭乗、終了、ピット状態をBridgeで判定 | 維持 |
| 安全反射 | 並走、停止車両、接触、ピット入口・出口等を決定論で発火 | V3の基礎として有効 |
| 燃料 | 実測燃費、残周回、必要量、余裕、耐久複数ストップを計算 | 既に強い。作り直さない |
| ピット | pit loss、pit exit forecast、復帰レンジ候補を計算 | 実走精度を磨く |
| 発話制御 | P0〜P5優先度、割込み、重複抑止、コーナー中保留 | OMORAYの重要資産 |
| Truth Gate | LLMの未確認数値・車両状態をTTS前に遮断 | 維持・単純化 |
| 記憶 | profile、raceHistory、車両×コース、デブリーフ証拠をlocalStorage保存 | 存在するが品質・移行性は不十分 |
| 診断・原価 | API、STT秒、TTS文字、生成・キュー・破棄・再生を記録 | V3効果測定に利用 |

### 現在クラウドへ残っている部分

| 経路 | V2の現状 | 問題 |
|---|---|---|
| PTT認識 | 原則Google STT | 短い定型質問でも従量原価と通信が発生 |
| 会話入口 | 通常入力はRailwayの `/api/chat` へ送る | 決定論的に答えられる質問も一度サーバーへ行く |
| 決定論的回答 | サーバー側ルーターが燃料、ルール、ピット等をAnthropic前に返す経路あり | Anthropicは回避できてもRailway往復と複雑性は残る |
| 自由会話・判断 | Anthropicを利用 | V3でも必要。対象を絞る |
| 人物理解の保存 | 会話を `[DRIVER_INSIGHT]` としてAnthropicへ送り、蒸留メモを作る | 保存のたびに原価。品質もLLM依存 |
| 音声 | 通常発話はGoogle TTSを都度呼ぶ | 定型文も同じ文章も再生成 |
| TTS失敗時 | 安全・期限付きピットだけWeb Speechへフォールバック | コスト削減用の通常経路にはなっていない |
| 文脈投入 | profile、車両×コース記憶、燃料、週末、証拠、契約、履歴を会話ごとに組み立てる | 動的トークンが大きくなりやすい |
| ブリーフィング等 | 複数の `/api/chat` 経路が存在 | LLMが不要な定型部分との分離余地 |

### V2を誤解してはいけない点

- V2は「全部LLM」ではない。すでに決定論エンジンが相当量存在する。
- サーバーの `/api/chat` を呼んでも、ルーターで返ればAnthropic原価は発生しない。
- ただし通信、サーバー処理、TTS、STT、保守複雑性は残る。
- 現在のMemoryとデブリーフは配線・保存機能がある段階で、商品品質は未証明。
- Bridge内の既存コメントにある小文字の「v3」は過去の内部実装ラベルであり、今回の製品アーキテクチャ **OMO-PW V3** とは別。

## V3で変更する部分

### 変更しない中核

- BridgeによるiRacing shared memory取得。
- 燃料・残周回・ピット・安全の権威計算。
- P0〜P5発話優先度と安全割込み。
- Truth Gateとfail-closed。
- Anthropicによる自由な相談・判断。
- Google音声品質が必要な自由会話。
- ドライバーがエンジニアへ反論・相談し、作戦を変更できること。

### 変更対象

| # | V2 | V3案 | 狙い |
|---:|---|---|---|
| 1 | 入力後は基本 `/api/chat` | ローカルIntent Routerを最初の入口にする | 不要なサーバー往復とLLM候補を除去 |
| 2 | サーバーで決定論回答 | 数値・状態質問はPC内で文章化して即答 | 低遅延・低原価・オフライン耐性 |
| 3 | 定型文もGoogle TTS | キャッシュ済み音声・事前生成フレーズを優先 | TTS原価削減 |
| 4 | PTTはすべてGoogle STT | 短い定型命令だけローカル認識を試験し、曖昧・自由会話はGoogle | 双方向品質を壊さずSTT削減 |
| 5 | 多量の動的文脈を毎回送る | その判断に必要なFact Cardだけ送る | トークンと誤判断を削減 |
| 6 | 記憶蒸留を都度LLM | 数値・選択・明示メモは構造化保存。人物洞察のみ低頻度LLM | Memory原価と幻覚を削減 |
| 7 | デブリーフが質問中心 | 実測差分・異常・Plan結果をローカル抽出後、意味がある論点だけAI対話 | しょぼい総括を減らす |
| 8 | 発話候補生成後に破棄あり | 話す決定を先に行い、その後でTTS生成 | 未再生TTSをなくす |
| 9 | 個々の機能が別経路 | Fact Card、Decision Card、Radio Directorの三層へ整理 | テスト容易性と再利用性 |
| 10 | 原価は事後集計中心 | ルートごとの回避額、キャッシュ率、LLM到達率を表示 | V3が本当に安いか証明 |

### V3の処理境界

```text
テレメトリ／PTT
      ↓
Local Fact Engine
  燃料・周回・GAP・順位・安全・ピット・履歴
      ↓
Local Intent Router
      ├─ 数値／状態／定型命令 → Local Reply → Cached/Local Voice
      └─ 相談／判断／作戦変更 → Compact Fact Card → Anthropic
                                             ↓
                                      Google TTS
      ↓
Radio Director
  優先度・沈黙・発話窓・重複・安全割込み
```

## RaceLabから取り込む候補

### A. 最優先で取り込む

#### 1. 「2分以内に走れる」導入思想

RaceLabの強さは機能数以前に、ダウンロード、インストール、起動が簡単なこと。

OMORAYへの変換:

- iRacing起動を検知してBridgeとPITWALLを自動開始。
- 初回だけマイク、音量、PTT、エンジニアを設定。
- 次回以降は設定画面を見ずに無線が使える。
- 更新、接続、復旧を利用者へ考えさせない。

評価: **必須。現在の導入負担は商品価値を消す。**

#### 2. Tool Managerの思想

RaceLabはSimHub、Crew Chief、Trading Paints等を自動起動・終了する。

OMORAYへの変換:

- 他ツールの存在を検知する。
- Crew Chief併用時は重複するスポッター発話を抑える。
- RaceLab併用時は表示を否定せず、OMORAYは判断無線へ集中する。
- 希望者だけiRacingと一緒に関連ツールを起動・終了する。

評価: **自動起動は高価値。万能ランチャー化は後回し。重複発話回避の方がOMORAYらしい。**

#### 3. ローカル計算・低限界費用

OMORAYへの変換:

- 確定値、集計、定型回答はローカル。
- 同じ音声は再生成しない。
- 一度得たコース・車両データを再利用する。
- LLMを「判断の追加価値」に限定する。

評価: **V3の中核。全面採用。**

#### 4. Data Blocksの思想

RaceLabは情報を小さな再利用部品として扱う。

OMORAYへの変換:

- Fuel Fact、Traffic Fact、Weather Fact、Pit Fact、Rival Fact、Driver Factを独立した構造体にする。
- LLMへ生テレメトリや巨大な文章を送らず、必要なFactだけ組み合わせる。
- 同じFactをブリーフィング、レース、デブリーフで再利用する。

評価: **見えない裏側として非常に有効。V3設計の中心にする。**

#### 5. Smart Layoutsの思想

RaceLabは車両・シリーズ・セッションで表示を自動切替する。

OMORAYへの変換:

- Smart Radio Profileとして、Practice、Qualify、Sprint、Endurance、Wetで発話ルールを自動切替。
- GT3 Sprintでは簡潔、耐久では燃料・スティント、雨では路面変化を優先。
- ドライバーにモードを毎回選ばせない。

評価: **画面を真似ず、無線ディレクターへ翻訳すれば強い。**

#### 6. Race Eventsの思想

RaceLabは追越、接触、ピット、順位変動を時系列で残す。

OMORAYへの変換:

- レース中の重要イベントと、その時のPITWALL判断・ドライバー回答を一つのTimelineへ保存。
- デブリーフはTimelineから最大3件だけ選ぶ。
- 「何が起きたか」ではなく「判断が正しかったか」を検証する。

評価: **現在のデブリーフを商品品質へ近づける最短候補。**

### B. 次段階で取り込む

#### 7. Series Module／Race Briefing

OMORAYへの変換:

- 日本の対象シリーズについて、開始時刻、レース長、SOF傾向、参加台数、過去結果をキャッシュ。
- 出走前に「今回のレースで重要な3点」だけ音声または短いカードで提示。
- 公開API・利用規約に従い、取得可能な情報だけ使う。

評価: **集客と継続には強いが、まずライブ無線品質を優先。**

#### 8. Driver Tagging

OMORAYへの変換:

- 「この相手は安全」「前回接触した」「同チーム」「追い方が強い」等を利用者が明示保存。
- iRatingだけで相手の危険性を断定しない。
- 自動で人格評価を生成せず、事実と本人タグを分ける。

評価: **Rival Memoryとして面白い。プライバシーと誤認に注意。**

#### 9. Fuel Sharing

OMORAYへの変換:

- 耐久のドライバー交代時に燃料、予定停止、タイヤ、直前の問題、Planを共有。
- チーム全員の会話を無差別共有せず、必要な運用Factだけ渡す。

評価: **耐久商品として強い。単独GT3品質の後。**

#### 10. 無料→Proの低摩擦導線

OMORAYへの変換:

- 無料は接続確認、ローカル安全・数値機能、短い体験。
- 有料入口は期限またはAI判断回数を明示した低価格商品。
- 本体は双方向AI判断、作戦変更、継続記憶。
- 「無料だから後で使う」を防ぐため、AI体験の開始期限を設ける。

評価: **思想は採用。ただしRaceLabの€4.90無制限は真似ない。**

### C. 条件付き候補

#### 11. Community Layout Library

OMORAYへの変換候補:

- 無線頻度プリセット。
- 日本のGT3、耐久、初心者向け等のRadio Profile。
- 将来的に実績あるエンジニア監修プロファイル。

評価: **初期は不要。人格・品質がばらつき、ブランドを壊しやすい。**

#### 12. Commercial License

OMORAYへの変換候補:

- 日本のSIM施設、ショップ、チーム、イベント向け座席ライセンス。
- 来場者が短時間でリアルエンジニア体験を得られるデモモード。

評価: **日本で体験を広げる販路として有力。個人版安定後。**

#### 13. Lifetime Purchase

評価: **そのまま真似ない。** RaceLabは限界費用が低いが、OMORAYはAI従量費が続く。買い切りにするならローカル機能のみ、AIは別枠が必要。

## 真似るべきでないもの

| 候補 | 理由 |
|---|---|
| 29種類以上のOverlay競争 | RaceLabの得意領域。OMORAYの人員と目的を分散する |
| 全SIM同時対応 | iRacingで深さと信頼を証明する前に品質が薄まる |
| €4.90でAI無制限 | 高対話利用者だけで赤字になる |
| 生テレメトリの無期限大量保存 | 保存、同意、削除、漏えい対応が増える。必要なFactと証拠に絞る |
| UI、文章、画像、名称の模倣 | 法的・ブランド上不要。思想をOMORAY体験へ変換する |
| 「AI」「Smart」の言葉だけ付ける | 実際の判断価値がなければ信頼を失う |
| 便利ツール全部入り | レースエンジニアの焦点を失う |

## Yujiの判断が必要な境界

最初のV3実装候補は次の小さな一塊にできる。

1. 燃料、残周回、GAP、順位、ピット状態の質問をPC内で分類する。
2. PC内の権威値から短い返答を作る。
3. 同じ定型音声をキャッシュする。
4. 判断・相談・作戦変更だけ既存Anthropic経路へ送る。
5. LLM到達率、回避額、TTSキャッシュ率を測る。

この範囲なら双方向体験を維持したまま、V3の原価仮説を最短で実測できる。Series Module、チーム共有、競合ツール管理、料金変更は含めない。
