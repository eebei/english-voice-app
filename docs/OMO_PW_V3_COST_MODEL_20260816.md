# OMO-PW V2 / V3 原価モデル

更新日: 2026-08-16 JST

## V3の定義

OMO-PW V3は、RaceLab型の低限界費用構造を取り入れながら、OMORAYが譲れない双方向のレースエンジニア体験を残す。

> ローカル計算と再利用可能なデータで事実を作り、クラウドAIは状況判断・相談・作戦変更にだけ使う。

V3は画面機能を増やす版ではない。ピット側で情報を処理し、ドライバーにはリアルな無線体験を返すための原価・判断アーキテクチャ刷新である。

## 処理方式の比較

| 処理 | OMO-PW V2 | OMO-PW V3 |
|---|---|---|
| テレメトリ取得 | Bridgeでローカル | 継続 |
| 安全コール・状態判定 | Fast Laneと一部ローカル処理 | 原則ローカル・決定論 |
| 燃料、残周回、ギャップ、順位 | 一部は計算済みだが会話経路でLLMを使う場合あり | 数値質問はLLMを通さず即答 |
| ピット窓・復帰位置 | 決定論＋会話層 | 決定論で候補を作り、判断が必要な時だけLLM |
| 音声認識 | Google STT中心 | 当初は品質優先でGoogleを残し、短い定型命令からローカル認識候補 |
| 音声合成 | Google TTS中心 | 定型無線を事前生成・キャッシュ。自由会話だけクラウドTTS |
| LLM | 通常会話、判断、文章生成 | 相談、優先順位、矛盾解消、Plan変更、意味あるデブリーフに限定 |
| 記憶 | ローカル履歴・車両×コース記憶 | 構造化数値はローカル、判断に必要な要約だけLLMへ投入 |
| デブリーフ | 質問・保存配線はあるが品質未実証 | 実測差分から改善候補を生成し、価値がある時だけ対話 |
| 発話 | 生成後に破棄される可能性あり | 話すと決めてから生成。重複・低価値発話は生成前に止める |

## 費目別の想定

削減率は設計目標であり、実装後にRevenue Dashboardで実測して置き換える。

| 費目 | V2 | V3の処理 | V3初期削減目標 |
|---|---|---|---:|
| Anthropic | 会話・判断・一部定型応答 | 判断を要する双方向会話のみ | 65〜85% |
| Google TTS | 多くの発話を都度生成 | 定型音声キャッシュ、短文化、生成前抑止 | 50〜75% |
| Google STT | PTT音声を都度送信 | 当初維持。定型命令のローカル化を段階導入 | 0〜40% |
| Railway/API | 全クラウド経路を処理 | LLM/TTSリクエスト減。認証・同期は維持 | 10〜30%の負荷減を期待、料金はプラン次第 |
| DB | 利用・課金・診断ログ | 構造化履歴、音声キャッシュ索引が増える | 初期は微増 |
| オブジェクト保存 | 限定的 | 必要な証拠・キャッシュのみ。生テレメトリ無期限保存はしない | 初期は月数ドル以内を目標 |
| 決済 | Stripe手数料 | 同じ | 変化なし |
| サポート | 手動導入が残る | 自動起動、自己診断、復旧で削減 | 金額は導入実績後に測定 |
| ユーザーPC | Bridge中心 | 計算・キャッシュ・一部認識を追加 | 会社側従量原価を利用者PCへ移す。CPU上限を設ける |

## 実測を基にした月間変動原価

V2は2026-08-09〜08-14の実測行動を30日に延長した参考値。V3は同じ利用行動に対して、API変動原価を50〜70%削減できた場合の範囲。Railway、Stripe、税、返金、サポートは含まない。

| 利用傾向 | V2月間変動原価 | V3想定 | 削減額 |
|---|---:|---:|---:|
| 八木型 | `$5.49` | `$1.65〜2.75` | `$2.74〜3.84` |
| Yuji型（高対話密度） | `$18.97` | `$5.69〜9.49` | `$9.48〜13.28` |
| まーぼー型 | `$4.46` | `$1.34〜2.23` | `$2.23〜3.12` |
| 観測3人合計 | `$28.92` | `$8.68〜14.46` | `$14.46〜20.24` |
| 観測平均/人 | `$9.64` | `$2.89〜4.82` | `$4.82〜6.75` |

平均は3人だけの小標本であり、顧客原価予測として確定しない。特に高対話利用者の上限管理が必要。

## 参考粗利

観測平均行動が続き、V3変動原価が `$2.89〜4.82/月` になった場合。Stripe、固定費、税、サポートを差し引く前。

| 月額 | V2観測平均の粗利率 | V3想定粗利率 |
|---|---:|---:|
| `$9.99` | 3.5% | 51.8〜71.1% |
| `$19.99` | 51.8% | 75.9〜85.5% |
| `$29.99` | 67.9% | 83.9〜90.4% |
| `$34.99` | 72.4% | 86.2〜91.7% |

`$9.99`はV2では継続月額として危険。V3でもStripe・固定費・サポートと高密度利用を考えると、無制限本体価格ではなく、期限または利用枠のある入口商品として検討する。

## V3の原価KPI

1. LLM呼出し率: 全ドライバー発話のうち何%がAnthropicへ到達したか。
2. 決定論的即答率: LLMなしで正しく回答できた割合。
3. TTSキャッシュヒット率。
4. 生成後未再生TTS率: 目標0%に近づける。
5. 1セッション・1完走・1有効判断当たり原価。
6. 高対話利用者の月間P95原価。
7. 原価削減によって回答品質、自然さ、双方向性が落ちていないか。

## 実装優先順位

1. 数値質問（燃料、残周回、ギャップ、順位、ラップ）のLLMバイパス。
2. 安全・定型無線の事前生成音声またはローカルキャッシュ。
3. 発話抑止をTTS生成前へ移動し、未再生生成をなくす。
4. LLMへ送る履歴を構造化要約し、トークンを削減する。
5. Plan A/B/Cの候補計算はローカル、選択・説明・相談だけLLMにする。
6. デブリーフは全データを送らず、実測差分と異常候補だけを渡す。
7. 定型PTT命令のローカル音声認識を品質・CPU・日本語精度を測って判断する。

## V3で守るもの

原価削減のために、次は削らない。

- 自然な双方向会話。
- ドライバーが異議を出し、作戦を相談・変更できること。
- 状況が曖昧な時に確認すること。
- 人格と無線のリアル感。
- 根拠がない時に断言しないこと。

削るのはAI体験ではなく、AIを使う必要がない処理である。
