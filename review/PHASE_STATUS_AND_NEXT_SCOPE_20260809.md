## Phase Cの実走ゲート

以下を満たすまでPhase Dへ進めない。

1. 同一GT3・同一コース・Green条件で、ピット出口予測を少なくとも4本有効採点する。
2. 各Runで`PIT EXIT SHADOW forecast`と`actual`が同一`snapshot_id`で対応する。
3. 4本中3本以上で実順位がBest〜Worst内に入る。
4. Likely順位の平均絶対誤差が2.0台以内である。
5. 4本目で予測補正の有効化を確認する。
6. 外れたRunは補正値を手修正せず、生ログ・リザルト・入力値から原因を分類する。

## Phase D/Eの着手ゲート

Phase Cを通過し、さらに次を満たした場合だけ戦略比較へ進む。

- 同条件3本以上の有効なpit-loss校正がある。
- 燃料計算は実測消費・残り周回authority・安全マージンを明示できる。
- `pit_now`、`pit_next_lap`、延長案を同一snapshotで比較でき、比較不能時は不利と捏造せず`unavailable`にする。
- Critical／Spotterが戦略・コーチング発話を中断できる通信優先制御を維持する。

## Phase P — Personal Practice Profile（前倒し）

現テスターはVRSで自分に合う複数車種を実走・比較しており、その練習データは再取得できない貴重な検証資産である。したがって、ドライビングを評価・指示する機能より先に、**本人の練習データをPITWALLが安全に持ち越す基盤**を初期実装した。

これはPhase C〜Eの戦略判断を置き換えない。戦略エンジンと並行して、テスターの次回セッションまでに価値を届けるための限定スコープとする。

### 初期実装の範囲

1. ユーザーが明示的に選択した**本人の**iRacing `.ibt`、必要なら `.sto` をローカル取込みする。VRSアカウントへのログイン、スクレイピング、自動取得は初版に含めない。
2. 車種、コース、セッション種別、路面温度帯、ラップタイム帯、セットアップ有無を抽出し、**要約だけ**をローカル保存する。生テレメトリーは保存・送信しない。
3. `car × track × setup fingerprint`単位の読取り専用プロフィールを生成する。
4. 現在セッションの車種・コース・セットアップ指紋と照合し、`matched / mismatch / unknown`を返す。
5. Lunaには、生ログでなく根拠付きの短いプロフィールだけを渡す。セットアップ不一致時は、過去の走行傾向を断定に使わない。

### 初期実装で保存する事実

- 車種、コース、セッション日時、走行周回、有効ラップ、ラップタイム帯
- 路面温度帯、ラップタイム帯など、選択された本人ログから再現可能な観測値
- セットアップファイルまたはテレメトリーから**実際に取得できた場合だけ**の設定指紋
- 取得不可／ユーザーがアップロード無効にした設定は`unknown`

### 初回に言ってよいこと／言ってはいけないこと

- 一致時：`鈴鹿・この車・近い設定で、過去に安定したラップ帯がある。`
- 不一致時：`鈴鹿の過去データはあるが、今回は設定が異なるため参考扱い。`
- 禁止：VRSコーチ／データパックの走行データを取り込むこと、一般論を本人の癖として断定すること、根拠のないリアルタイム助言をすること。

### テスターで先に確認すること

- 3名それぞれが持つ本人ログで、対象車種・鈴鹿等の車種／コース識別が安定するか。
- VRS由来の個人データに必要なファイル形式・セットアップ情報の有無。
- 同じ車種でもセットアップ変更を区別する指紋が作れるか。
- データ量、ローカル保存期間、削除操作、同意画面が実用的か。

### 完成の判定

- 3名の本人データを、他者・コーチ・データパック情報を混入させず取込める。
- それぞれで車種・コースを正しく特定できる。
- セットアップ一致／不一致／不明を捏造せず表示できる。
- 要約プロフィールを個別に削除できる操作は今後の候補であり、現状はブラウザのローカルデータ削除で消去できる。
- まだライブコーチングを自動発話しない。

## Phase F — ドライビングコーチング（保留スコープ）

市場調査で、ABS、初期制動、ブレーキリリース、旋回、最低速度、トラクションについて「自分のデータで、なぜ遅いか知りたい」という課題は確認された。しかし、PITWALLはまずレース中の戦略判断を信頼可能にする。

したがって、ドライビングコーチングの**ライブ助言**は、Phase Pで本人データの帰属・照合を確立し、Phase D/Eの戦略機能にある程度の目処がついた後に実装する。

- Phase Cの実走ゲートを通過している。
- Phase Pで、対象車種・コース・セットアップ一致度を根拠付きで返せる。
- Phase Dの少なくとも燃料・ピット比較が、実走ログで根拠と結果を追跡できる。
- 現行のCritical > Spotter > Strategy > Coaching > Casual優先度を実走で守れる。
- コーチングの根拠に必要なテレメトリー（車種、トラック、コーナー区間、入力、タイヤ／ABS等）が取得・検証可能である。

### 再開時の最小縦切り

最初からライブ全周コーチを作らない。LMU GT3またはiRacing GT3の一車種・一コースで、セッション後に一つのコーナー群だけを扱う。

- **事実**：入力・速度・ABS・ラップ差の観測値。
- **推定**：時間損失の主因候補。根拠不足なら`unavailable`。
- **提案**：次スティントで試す一つの操作変更。
- **禁止**：一般論をドライバー固有の原因として断定すること、走行中にCritical／Spotterを遮ること、未検証の基準ラップを真実として扱うこと。
