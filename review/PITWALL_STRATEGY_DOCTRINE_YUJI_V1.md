# PITWALL 戦略ドクトリン — Yuji 実走知識 v1

作成: 2026-09-02 JST  
位置づけ: PITWALL V4以降の戦略判断・記憶・デブリーフの中核仕様

## 1. 目的

PITWALLは、燃料残量を読み上げるだけの反射ツールではない。ドライバーの位置、前後の集団、燃料、ピットロス、ライバルの反応を組み合わせ、**次に一つの推奨判断を出し、その結果を次回へ活かす専属レースエンジニア**である。

## 2. Fuel Window の定義

Fuel Window は「燃料が空になる周」ではない。次のスティントを成立させる給油量と、ピットへ入ることで得られる順位上の利益を同時に評価できる時間帯である。

Lunaは次の順で判定する。

1. 現在燃料、実測燃費、残り周回から、完走必要量を計算する
2. 給油後に次のスティントを走り切れるか確認する
3. 前方集団の台数・ペース・ピット未実施を確認する
4. ピットロスと復帰時の交通を見積もる
5. アンダーカット利益がある場合、**「この周に入る」または「あと何周待つ」**の一つを推奨する

「Fuel Windowが開いたら教えて」は、単なる燃料警告ではなく、ピット判断に使える状態になったら知らせるという要求として解釈する。

## 3. GT Sprint／IMSA Fixed の中団アンダーカット

スタートが中団で、前方に4〜6台程度の集団があり、自分のペースが集団より速い場合、ステイアウトすると交通により燃料と時間を失うことがある。

代表的な成功条件:

- 前方集団が次周以降にピットへ入る見込み
- 自分は必要最小限の給油で次のスティントを成立できる
- ピットアウト後に後方集団へ捕まらない
- 前方集団がピット後に戻ってくる前に、クリーンなトラックへ合流できる

失敗条件:

- ピットアウト後に遅い後方集団へ引っ掛かる
- 想定より自分のペースが上がらない
- 相手がピットへ入らず、アンダーカット対象が消える

したがって、Lunaは成功例だけでなく、失敗例も次回判断へ利用する。

## 4. 上位争いの1周ずらし

P1〜P2付近では、燃料を限界まで使ってから入るのが基本だが、1周早く入ることで相手との同時ピットを避け、順位が入れ替わる可能性がある。

この判断には次を含める。

- 相手が同時に反応する可能性
- 1周分のアンダーカット効果
- 空いたトラックへ出られるか
- ピットロスと再合流順位

この領域では「Plan A/B」を提示してよい。ただし、1周差だけを理由に機械的に別プランを増やさない。

## 5. プラン生成の形式

Plan A/B/Cは、周回数だけを1周ずつずらした候補では不十分である。各プランに次を必須とする。

```json
{
  "plan": "B",
  "action": "pit_now",
  "pit_lap": 10,
  "fuel_add_l": 23.8,
  "pre_pit_position": 13,
  "expected_rejoin_position": {"low": 9, "high": 6},
  "target_group": "前方4台",
  "success_conditions": ["相手が次周に反応", "アウトラップで交通なし"],
  "failure_conditions": ["後方集団に拘束", "自分のペース低下"],
  "confidence": "estimated"
}
```

`expected_rejoin_position` は一点の断定値ではなく、交通とライバル反応を含む範囲で保持する。

## 6. Lunaの推奨発話

曖昧な選択肢の列挙ではなく、一つの判断を先に出す。

> 今ピットへ入ろう。前の集団をアンダーカットできる見込みがある。相手が次周に反応すれば差は縮まるけれど、私はこの周を推すね。

データが不足する場合も、機械的な「その数値は確認できない」ではなく、何が不足しているかを説明する。

> 前方4台の正確なピット反応がまだ揃っていないから、成功順位までは成立しないよ。次の計測で更新するね。

## 7. 結果の答え合わせ

レース後に保存する項目:

- 推奨プランと根拠
- 実際のピット周・給油量・ピットロス
- ピット前順位とブレンド後順位
- 対象ライバルの実際のピット周
- 成功／失敗
- 失敗理由（交通、ペース、相手の反応、接触など）
- ドライバー訂正

次回の同車種・同コース・同形式では、成功例と失敗例を同じ重みで候補へ渡す。成功例だけを参照してはならない。

## 8. 記憶への反映契約

ドライバー発言は即時に恒久事実へしない。

1. 実走データを保存
2. Lunaの推奨と結果を保存
3. ドライバーの訂正を `disputed()` として保留
4. 次の観測またはデブリーフで照合
5. 合意後にドクトリン候補へ昇格

これにより、Yujiの経験を製品の核へ取り込みつつ、誤ったピット周・順位・燃料値の固定化を防ぐ。

## 9. 受入条件

- Fuel Windowを燃料警告と区別して説明できる
- 中団アンダーカットの成功条件と失敗条件を両方提示できる
- Plan A/Bが周回差だけでなく、対象集団・給油量・復帰順位範囲を持つ
- 実走結果が次回の同条件判断へ注入される
- ドライバー訂正が質問や雑談へ誤分類されず、`disputed()`へ進む
- 推定値は推定と明示し、権威データのように断定しない

この6条件を満たさない実装は、PITWALLの戦略ドクトリン適用済みとは扱わない。
