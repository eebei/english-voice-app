## 1. 最優先の目的

Lunaを、保存された部品を個別に呼ぶだけの仕組みから、**回答・提案・デブリーフの前に必ず自分の記憶を検索する専属レースエンジニア**へ変更する。

1. 考えて答えを返す
2. 自ら提案する
3. 余計なことは言わない
4. 最後にデブリーフで賞賛と反省を行い、次戦へ使う

設計図やモジュールの存在では合格にしない。**実製品経路の往路と復路が両方通った実出力**を必要とする。

この順番を共通契約とする。

```text
質問・現在のレース状況
  → Luna Memory Boxを横断検索

  → 意図を理解

  → 使用した記憶IDと根拠を記録
  → 結果・訂正・評価をMemory Boxへ戻す
  → 再起動後／次戦に再取得して使う
```

従来の「intentを分類し、その個別機能が必要なら記憶を取る」だけでは不可。呼出しを実装していない質問で記憶が死ぬため、**回答生成より前の共通思考入口**にする。

- 公式レース結果

検索キーは少なくとも `user/cust_id + session/subsession_id + track + car + series + time` を持つ。別利用者の記憶は絶対に混ぜない。

## 5. 内部製品経路テスト

最低限、次を実際の回答経路へ入力する。

- 今日の走りはどうだった？
- 周囲が危なかったから抑えたけど、判断は正しかった？
- 前回のLe Mansを覚えてる？
- Plan Aは成功した？
- 今回の改善点は？
- 次のレースで何を意識すればいい？
- 俺の走りは安定している？
- Fuel Windowが開いたら教えて

### 合格条件

1. 正しいsession/userの記憶だけを取得する。
2. P10→P8、1x、+50、Plan A、本人説明を捏造なく使う。
3. 危険回避を単なる遅さと誤判定せず「結果を持ち帰った走り」と評価する。
4. 実測していない「メートル単位のライン再現」等を言わない。
5. 保存後のアプリ再起動相当でも取得できる。
6. 次戦ブリーフィングで前回の成功を一度だけ引用し、重点を一つ提案する。
7. Lunaの実回答／発話から、使用記憶ID→評価→公式結果・本人説明まで逆引きできる。
8. Lunaの新しい評価が保存され、次ターンで再利用される。

### 往路

```text
source → save → restart → retrieve → inject → decide → actual reply/TTS
```

### 復路

```text
actual reply/TTS → retrieved memory IDs → evaluation record → official facts / driver statement
```

一段でも切れれば不合格。保存だけ、取得だけ、LLM注入だけ、UI表示だけ、テスト関数だけでは完成ではない。

### 必須変異試験

- 検索を外す
- session/user identityを変える
- debriefを削除する
- 保存成功・取得失敗にする
- Lunaへの注入を切る
- 実回答／TTS出口を切る
- 使用記憶IDのtraceを切る
- 再保存または次ターン再取得を切る

各破壊でテストが赤くならなければ検査自体が不合格。
