## 2. ここから出る要件（`disputed()` へ追加してほしい）

Codex の限界記述「これはラベルの独立再判定であり、現行routerが16件を正しく処理できることを意味しない」に同意した上で、
**判定窓そのものを契約に含めたい。**

1. **訂正は、受理されるまで開いたままにする。** 直前1発話の窓では、14分後・切断を挟んだ再提出を取りこぼす。
   `disputed()` の状態は、**Luna が受理を発話するまで解決しない**。
2. **同一 axis への再提出は、新規報告として扱わない。** 未解決の `disputed` が同じ axis に存在する間、
   同種の発話は**再提出**として同じイベントへ束ねる。
3. **言語切替を escalation シグナルとして扱う。**
   日本語で訂正 → 受理されず → **英語で同内容**、が2レース連続で観測されている。
   これは「システムが理解していない」とドライバーが判断した証拠であり、
   **無視されたことの機械可読なサイン**として使える。

3 は当方の推測を含む。**2件の観測しかない。** ただし 62→64 と 11:59→12:03 は
同一人物・同一状況・同一結末（受理されるまで繰り返す）であり、偶然にしては型が揃っている。
7月分ログ（holdout 289件）で検証可能なので、**採用前に測る。**
