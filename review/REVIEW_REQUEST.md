## 再レビュー条件への対応

### ✅ 1. 優先度を bridge から実再生まで保持（P0-1）

**確認した事実**：`injectRadio()` は `speak(text, data.trigger==='crash_check')` を呼んでおり、**crash_check 以外の全ての安全コールが既定の P4** に落ちていた。停止車両・速いクラス接近・ピット手順が「情報」と同列だった。指摘のとおり安全保証は成立していなかった。

**修正**：
- `broadcast()` 内（＝優先度を判定している唯一の場所）で `event['prio'] = prio` を付与し、renderer まで運ぶ
- `injectRadio()` は `speak(text, {prio: data.prio, kind: data.trigger, dedupeKey: ...})` を渡す
- **crash だけ boolean で昇格させる旧方式は廃止**

### ✅ 2. P0 割り込みのデッドロック解消（P0-2）

**確認した事実**：`stopCurrentAudio()` は `isSpeaking=false` にするが **`draining` を戻していなかった**。`drainQueue()` は `draining || isSpeaking` で return するため、`pause()` が `onended` を出さない経路では **watchdog（最大40秒）まで安全コールが待たされ得た**。

**修正**：割り込みを単一の状態遷移にした。`stopCurrentAudio()` で `onended` を外し、watchdog を解除し、`draining=false` / `currentSpeakPrio=9` に戻し、`setTimeout(drainQueue,0)` で**割り込んだ側を即座に再生**する。

### ✅ 3. traffic-shape テストを実際に実行（P0-3）

**確認した事実**：指摘のとおり `process.exit()` が既存テスト直後にあり、**追記した形テストに到達していなかった**。前回依頼書の「5ケースで単体テスト済み」は、あのランナーでは**成立していなかった**（Python 側で個別に実行した結果を書いてしまった）。

**修正**：`process.exit` を全テスト完了後へ移動。合計を集計して終了コードに反映。

### ✅ 4. ピットカウントダウンを閾値横断方式へ（P0-4）

**確認した事実**：`_dist_m <= _mark` 判定のため、90m 地点で初検出すると「150m」を読み、10m から始まると 150/100/50/20 を連続で読み上げ得た。

**修正**：
- 前回距離 `pit_prev_dist_m` を保持し、**`previous > mark >= current` の横断時のみ**発火
- **最初の有効サンプルで既に通過済みの mark は消化済みとして黙って捨てる**
- 距離が**近づいている時のみ**発火（逆行・ラップ跨ぎの飛びでは鳴らさない）
- コース復帰時に状態を白紙化。**初回入庫は学習のみでカウントダウンしない**

### ✅ 5. memory dump の経路と payload（P1-5）

**確認した事実**：`iracing_connected` の分岐が**先に return** しており dump に到達しなかった。さらに renderer は `{line:...}`、bridge は `msg.get('text')` を読んでおり**不一致**だった。

**修正**：`iracing_connected` の処理を**1か所へ統合**し、payload key を bridge が読む **`text` に統一**。

### ✅ 6. multiclass 再武装にヒステリシス（P1-6）

**確認した事実**：発火が 5 秒で、再武装も実質同じ境界に依存していたため、**4.9↔5.1 秒の振動だけで再発火**できた。

**修正**：`MC_REARM_SEC = 8.0` を新設。**発火は 5 秒のまま、再武装は 8 秒超に離れた時だけ**。

### ✅ 7. ピット進入車の混入（P1-7）

**確認した事実**：`car_on_track[_mi] not in (2, 3)` で **2（approaching pits）を許容**していた。

**修正**：安全コールの対象を **`== 3`（on track）のみ**に限定。
