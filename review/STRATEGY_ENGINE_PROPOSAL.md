# Codex → Claude Code：PITWALL 戦略判断エンジン提案

**日付**：2026-07-21  
**起点となった実走**：アップデート前のオフィシャルレースで、P11走行中に「今ピットへ入ると何番手で復帰するか」と質問。Lunaは「確認する」「リアルタイムで見ないとな」「取り返せる」と返し、復帰順位も判断根拠も提示できなかった。  
**重要度**：商用品質の中核。SIMレーサーが期待する「状況を読み、結果が不確実でも、その場で判断と提案を返す」能力そのもの。

## 1. 結論

これはモデル性能の問題を主因としない。LLMは呼ばれており、P11等のライブ値も認識していた。しかし、復帰順位を出すためのピット総ロスと将来位置の計算器がなく、プロンプトにも「確認すると言え」と「確認すると言うな」が併存している。

個別の返答例をプロンプトへ足す対処ではなく、次の責務分離へ移行する。

1. **Bridge / Strategy Engine**：実値から候補戦略と予測レンジを決定論的に計算する
2. **LLM**：計算結果、リスク、ドライバーの意図を踏まえ、短い無線として提案する
3. **Speech Director**：優先度、割り込み、発話量を制御する

**LLMに数字を計算・推測させない。LLMには、根拠のある複数案から「今どれを勧めるか」と「どう伝えるか」を担当させる。**

## 2. 最優先：今ピットへ入った場合の復帰順位予測

### 必要な入力

- 現在の総合／クラス順位
- `CarIdxF2Time`等によるクラス全車の時間的位置
- 自車のピット入口までの残り時間
- コース固有のピットレーン走行ロス
- ボックス最低滞在時間
- 今回の給油予定量と給油レート
- タイヤ交換の有無と所要時間への影響
- 修理時間
- 他車のピット状態
- 値の取得時刻と鮮度

### 出力契約案

```json
{
  "type": "strategy_snapshot",
  "generated_at": 0,
  "valid_for_s": 3,
  "pit_now": {
    "total_loss_s": 27.4,
    "rejoin_position_best": 18,
    "rejoin_position_likely": 19,
    "rejoin_position_worst": 20,
    "gap_to_car_ahead_s": 2.1,
    "gap_to_car_behind_s": 1.4,
    "confidence": "medium",
    "confidence_reasons": ["pit transit calibrated", "2 nearby cars may pit"],
    "assumptions": ["fuel 18.0 L", "no tyres", "no repairs"]
  }
}
```

### Lunaの期待応答

- 高信頼度：`今ならP19復帰。P18の約2秒後ろ。`
- 中信頼度：`本線はP19。レンジはP18からP20。`
- 計算不能：`このコースのピットロス実測がまだ無い。今は復帰順位を出せない。`

禁止：`確認する`、`データ確認中`、`出てから見る`、根拠のない`取り返せる`。

## 3. 同じ基盤で扱う戦略領域

すべてを一括実装する必要はない。優先度順に同じ `strategy_snapshot` へ追加する。

### P0：即時判断

1. **BOX NOW / STAY OUT**
   - 今入る利得・損失、復帰順位レンジ、トラフィック
2. **給油量**
   - 残り推定周回 × 実測消費 + 安全余裕 − 現燃料
3. **ピットウィンドウ**
   - 最早／本命／最遅ラップまたは残り時間
4. **修理する／しない**
   - 修理秒数と走行影響、残り時間との比較

### P1：順位を取りにいく判断

5. **アンダーカット**
   - 前車とのギャップ、前車ペース、クリアエア、タイヤ／燃料条件
6. **オーバーカット**
   - 現在の自車ペース、前車のトラフィック、延長可能周回
7. **復帰トラフィック回避**
   - ピット後に集団へ刺さるか、クリーンエアへ出られるか
8. **PUSH / HOLD / SAVE**
   - 残り時間、燃料マージン、前後ギャップ、順位価値から選ぶ

### P2：レース全体の適応

9. **相手のピット反応**
   - 直接競合が入った時にカバーするか、逆を取るか
10. **マルチクラス交通の利用／回避**
    - 追いつく集団とピットタイミングの重なり
11. **天候変化への対応**
    - 路面状態、気温、残り時間。ただし予報データが無ければ未来を捏造しない
12. **セーフティカー／コーション対応**
    - 対応シリーズと取得可能データを確認してから実装
13. **最終盤の燃料セーブ量**
    - 必要セーブ率を数値化し、実行可能か判定
14. **チャンピオンシップ／SR優先**
    - 順位期待値だけでなく、事前に合意した目標を評価関数へ入れる

## 4. 設計原則

### 4.1 予測は一点ではなくレンジ

他車も動くため、復帰順位を常に一点断言しない。`best / likely / worst`と信頼度を持つ。

### 4.2 事実、仮定、提案を分離

- 事実：P11、燃料21.1L、P18まで26秒
- 仮定：18L給油、タイヤ交換なし、通常のピット通過
- 予測：P18〜P20復帰
- 提案：今入る／1周延ばす

ログにもLLM入力にも、この区別を保持する。

### 4.3 「確認中」という非同期のふりを禁止

現行チャット呼び出しは、その返答後に自律的に再計算して折り返す仕組みではない。即答できない場合は、欠けているデータを一言で明示する。

### 4.4 戦略提案には必ず根拠を一つ付ける

`今入ろう`だけでなく、`P19復帰だがクリアエアに出る`のように判断軸を返す。長文化は避け、詳細は再質問で答える。

### 4.5 ドライバーの意思を評価関数へ入れる

事前契約として最低限を保持する。

- 攻める／完走優先／SR優先
- タイヤ交換方針
- リスク許容度
- 合意したピット窓

途中で新しい根拠なく方針を変えない。

## 5. 現行コードで先に直すべき矛盾

現行 `prompts.js` には次が共存する。

- セッション種別不明時に「実データを確認する」と言わせる
- ライブ欄に無い項目は「確認する」と言わせる
- エンジニアリング鉄則では「確認する／折り返す」を禁止する
- 後段の発話是正でも「データ確認中」を禁止する

最終規則を一つに統一する。

> 今このリクエスト内で計算可能なら即答する。計算不能なら、無い入力を明示して終える。後で折り返すと約束しない。

ただし、矛盾除去だけでは復帰順位は出ない。計算器の実装が本体である。

## 6. 段階的な実装案

### Phase A：嘘を止める

- 矛盾プロンプトを整理
- `確認中`等を回帰テストで禁止
- 戦略質問に必要入力が無い場合の構造化された `unavailable_reason`

### Phase B：ピットロスの校正

- 各コース×車種／シリーズで、通常ラップとピット通過ラップの差を記録
- ピット進入、ボックス停止、退出の時刻をログ化
- 固定値ではなく実測分布（中央値とばらつき）を保存

### Phase C：復帰順位予測

- `CarIdxF2Time`上の全車位置へ予想総ロスを重ねる
- best / likely / worstを算出
- 単体テスト、リプレイテストを追加

### Phase D：戦略比較

- `BOX NOW`、`+1 LAP`、`+2 LAPS`を同時評価
- 復帰順位、交通、燃料余裕を比較
- LLMへ候補と推奨理由を渡す

### Phase E：アンダーカット等へ拡張

- 実測されたタイヤ／燃料／ペース情報だけを使う
- データの無い効果は仮定として明示し、学習データが溜まるまで低信頼度にする

## 7. 検証条件

最低10〜20回の実ピットについて、次を保存する。

- 予測時刻
- 予測best / likely / worst順位
- 予測総ロス
- 仮定したサービス内容
- 実際の総ロス
- 実復帰順位
- 予測レンジ内だったか
- 外れた理由（他車ピット、事故、混雑、計測不良等）

初期合格条件案：

- `確認する／データ確認中／取り返せる`だけの回答：0件
- 復帰順位の実値が予測レンジ内：80%以上
- likelyの誤差：中央値±1台以内
- 判断生成から発話開始まで：実走上許容される時間内（別途計装）

## 8. 今回の依頼範囲

Claude Codeには、まずPhase A〜Cの設計・実装案、取得できるiRacing SDK変数、欠ける入力、テスト方法を提示してほしい。いきなり全戦略を実装せず、**「今ピットなら何位復帰？」を正しく即答できる縦切り**を完成させる。

実装後は必ず次の順序を守る。

1. 機械テストと変異テスト
2. Codexによる差分・計算式・証拠能力の独立レビュー
3. ビルド
4. Yujiによる実走で予測と実復帰順位を照合
