# Claudeレビュー依頼：高速クラス優先のGAP紐付け（2026-09-04 Le Mans）

## 目的

2026-09-04 IMSA Le Mans 実走で、Yujiの観測では次の並びがあった。

```text
自車（GT3）
  └─ 同クラスGT3：約5秒後方
       └─ 高速クラスGTP：約6秒後方
```

GTPはGT3よりラップが大幅に速く、接近率・危険度が圧倒的に高い。したがって、5秒という最短距離をGTPに流用して「GTP、5秒」と発話してはいけない。発話の主対象はGTPであり、GTP自身の約6秒を使う必要がある。

## ログ上の確認

- `MC fire class=GTP nearest=5.7s gaps=[5.7]` はGTPイベントとして記録されている。
- ただし現行ログには、発話対象車両の `car_idx`・車番・class_id・GAPを同一レコードで残していない。
- そのため、GTPのGAPがGTP自身の値か、途中のGT3の値が混入したかを独立再現できない。
- 参照ログ：`/Users/yuji.s/Downloads/OMORAY-bridge-debug-20260904-0936.log`

## Claudeへの反証・再設計依頼

次を、実装前に反証して最善案を出してください。単に「クラス名はGTPで正しい」と結論しないこと。

1. **車両単位の原子レコード**
   - `car_idx / class_id / class_name / car_number / gap_s / relative_speed / timestamp / on_track` を同一候補レコードとして生成する。
   - クラスごとの最短GAPを選んだ後に別車両のクラス名を付ける経路がないか確認する。

2. **高速クラス優先**
   - まずGTPなど「自車より速いクラス」の候補を車両単位で抽出する。
   - 最近距離ではなく、`closing_rate`（GAPの縮小率）とクラス速度差を含めた接近優先度で主対象を選ぶ。
   - 同クラスGT3が5秒、GTPが6秒でも、GTPを主発話対象にする。

3. **発話例**
   - 主コール：`GTP、6秒で接近。`
   - 中間車両も安全上必要な場合のみ：`GTP、6秒で接近。間にGT3が1台、5秒。`
   - `GTP、5秒` のように別車両のGAPを流用する発話は禁止。

4. **発話直前の再検証**
   - dispatch直前に `event_id` と `car_idx/class_id/gap_s` の整合性を再検証する。
   - ポーリングが変わった場合は古い候補を破棄し、同一車両の最新値だけを発話する。

5. **診断の追加**
   - `MC_CANDIDATE_SET` として、候補車両を距離順ではなく車両ID付きで全件記録する。
   - 例：`[{car_idx:12,class:GTP,gap:6.0,closing_rate:0.8},{car_idx:21,class:IMSA23,gap:5.0,closing_rate:0.1}]`
   - 実走音声・字幕と照合できる発話イベントIDを必ず残す。

## 必須再生テスト

- ケースA：GT3 5秒、GTP 6秒、GTPの接近率が高い → 主発話はGTP 6秒。
- ケースB：GT3 3秒、GTP 7秒でもGTPが高速接近 → GTP 7秒を主発話。
- ケースC：GTP 6秒だが接近率が負（離脱） → GTP接近コールを出さない。
- ケースD：候補配列の順序を入れ替えても発話対象・GAPが変わらない。
- ケースE：class mapを一時的に誤らせた変異試験 → 検査が赤になり、誤クラス発話を許可しない。

## 合格条件

「GTPと発話できた」だけでは合格にしない。**高速クラスの正しい車両に、正しいGAPを結び付け、そのGAPを主発話し、中間車両は補足として扱えること**を合格条件とする。

Claudeは、上記設計で不足する点、過剰な点、より安全な代替案を数値・再生結果付きで返してください。実装は反証後に着手する。
