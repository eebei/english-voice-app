# Automated Diagnostic Telemetry — 月内必須課題

記録日: 2026-07-27  
期限: 2026-07-31  
状態: 未実装

## 目的

テスターや一般利用者に `OMORAY-bridge-debug-*.log` の手動送付を求めず、障害原因の特定に必要な診断イベントをPITWALLサーバーへ自動送信する。

## プライバシー境界

送信しない:

- 会話本文
- 音声データ
- 生のiRacingテレメトリ
- メールアドレス、アクセスコードなどの認証情報
- 自由入力された個人情報

送信する候補:

- build番号、匿名tester識別子、診断session ID
- アプリ起動、更新確認、認証、設定復元の成功／失敗
- STT/TTSの成功／失敗、失敗種別、処理時間
- iRacing接続／切断、INACTIVE_DRIVER遷移
- 発話安全窓の保留／再開／期限切れ
- SessionInfo解析台数とライブ車両数の不一致
- 燃費計算の成立／不成立と理由（数値本文ではなく状態を基本とする）
- セッションサマリー／記憶保存の成功／失敗

## 実装契約

- 既存Cost Telemetryとは目的と保存先を論理的に分離する。
- バッチ送信し、レース中の通信・CPU負荷を増やさない。
- 送信失敗時は件数上限付きローカルキューへ保存し、次回起動時に再送する。
- サーバー側でレート制限、保持期限、build別・失敗種別別の集計を設ける。
- 利用者向けPrivacy説明へ、収集項目・目的・非収集項目・再送動作を明記する。
- 実装後は自動テスト、独立レビュー、Windows実機でオフライン復旧を確認する。

## 出荷判定

「ログを送ってください」と利用者へ依頼せず、管理側だけで次の脱落地点を判定できること:

1. 起動しない
2. 更新できない
3. 認証できない
4. 設定が復元されない
5. マイク入力が届かない
6. STTが失敗する
7. AI回答は届くがTTSが鳴らない
8. iRacingデータが欠損・誤分類される
9. 燃費・記憶・サマリーが保存されない
