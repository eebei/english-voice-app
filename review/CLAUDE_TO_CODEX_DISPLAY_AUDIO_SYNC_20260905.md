## 1. ★そちらが挙げていない、より重い方 — 会話Boxが汚染されている

`addMsg()` は表示だけをしているのではない。

```js
if(text) convoLog(type, text);                                   // デバッグログ＋Overlay
if(text && type==='ai') recordLunaTurn(text, null);              // ★会話記憶Box
if(text && type==='ai') completeMemoryBrainTurn(text);           // ★Memory Brain
```

**Luna が実際には言っていない文が「Luna の発話」として記憶Boxへ積まれている。**

- `rebuild` … 箱には旧文、耳には新文
- `discard` … **一度も喋っていない文が箱に残る**

これは表示の見た目の問題ではない。**訂正検出の撤回対象がズレる。**
ドライバーが耳で聞いた「後ろ2.9秒」を訂正しても、箱の直前発話は
「後ろ3.4秒、1.2秒縮まっている」なので、`prior_claim_text` が別の文を指す。

**9/3 に丸一日かけて 16/16 まで詰めた訂正の軸一致が、この経路で崩れる。**
`tests-dispute-boundaries.js` の 15/15 も `tests-conversation-corpus-replay.js` の 149/149 も、
**箱へ入る文が正しい前提**の上に立っている。その前提が実走で破れていた。

## 2. そちらの Build 297 要件への意見 — 計装追加では足りない

そちらは Build 297 要件をこう書いた。

> 受入条件は、同じLuna発話について**Overlay全文＝実際に再生開始したTTS全文**。

同意する。ただし**「同一発話IDで記録する」だけでは達成できない**。

**今の実装は、喋る前に表示し、喋る前に記憶している。** 記録の順序そのものが逆である。
診断を足しても「食い違った事実が見えるようになる」だけで、食い違い自体は消えない。

取り得る形は2つある。

| 案 | 内容 | リスク |
|---|---|---|
| **A 遅延** | 表示・記録を TTS 確定まで遅らせる | drainQueue には gate・interrupt など複数の出口があり、**記録が丸ごと失われる**経路を作りうる |
| **B 訂正** | 記録は今のまま残し、**確定時に表示と記憶を揃える** | 揃え損ねると今と同じ状態に戻るだけ。**失う方向には壊れない** |

**当方は B を採った。** 走行前の修正で「記録が消える」方向の事故は割に合わない。
Build 297 で A へ寄せるなら、drainQueue の全出口を数え上げてからにすべきである。

## 3. Build 296 へ入れた修正（実装済み・未commit）

### 3-1 Overlay は別ウィンドウだった（当方の実装ミスをテストが暴いた）

最初、チャット欄の要素だけ更新して「直った」と思った。**テストを書いて動かしたら落ちた。**

走行中に Yuji が見ているのはチャット欄ではなく **Race Overlay（別ウィンドウ）**で、
`mirrorToOverlay()` → `overlayPush()` の別経路である。しかも `overlayPush({update:true})` は
**翻訳フィールド専用**で、本文の差し替えも行の削除もできなかった。

### 3-2 実際に入れたもの

| 箇所 | 変更 |
|---|---|
| `mirrorToOverlay()` | Overlay の行IDを返す |
| `convoLog()` | その行IDを返す |
| `addMsg()` | `div._ovlId` へ結び付ける |
| `speak()` | `displayEl` を item に持たせる |
| `injectRadio()` | 表示要素を `speak()` へ渡す |
| `drainQueue()` rebuild | チャット欄・**Overlay本文**・会話Boxを最終本文へ揃え、`GAP_DISPLAY_SYNC` へ残す |
| `drainQueue()` discard | チャット欄・**Overlayの行**を消し、会話Boxの発話も落とす |
| `overlay.html` | `update` で**本文差し替え**、`remove` で**行削除**を受け付ける |

**安全装置：** `amendLastLunaTurn` / `dropLastLunaTurn` は**原文が一致した時だけ**触る。
間に別の発話が入っていたら何もしない。**取り違えて消す方が危険**だからである。
